## TEMUAN UTAMA
=======================================================================

### 1. KNN (--knn) adalah penyebab tunggal collapse output

Gejala awal: output judger/mutation_judger/crossover_judger berupa teks
degenerate panjang ("1 1 1 1...", echo template), repair gagal 3x.

Mekanisme awal (RoPE offset): kv_knn_filter membuang token berlubang via
torch.gather. Key tersisa membawa fase RoPE posisi ASLI sementara panjang
fisik cache menyusut → token baru diposisikan dari panjang yang menyusut
→ RoPE desync → output degenerate.

Setelah fix RoPE re-rotasi (commit 53f7397), perilaku BERUBAH tapi masih
gagal — lihat Temuan #5 untuk analisis penuh.

Bukti: run tanpa --knn (latent_steps=40, use_realign=True) menghasilkan
parent dan mutation/crossover yang valid. Run dengan --knn collapse.

Catatan kritis: latent_steps + use_realign TIDAK menyebabkan collapse
(bertentangan dengan hipotesis sesi sebelumnya). Bisection lama yang
menyalahkan "akumulasi ~40 latent tokens" perlu direvisi.


### 2. Repair gagal bukan karena bug repair sendiri

Repair selalu gagal di run dengan KNN karena kv_consist (baseline
pristine untuk repair) dibangun lewat chain yang sudah korup oleh KNN.
Plus KNN diterapkan ulang di setiap attempt repair → makin korup.
Di kondisi bersih (tanpa KNN), judger langsung parseable → gate pass →
_gate_and_repair balikin lebih awal, repair tidak pernah dipanggil.
Repair BELUM divalidasi secara terisolasi; lihat item TODO.


### 3. Gate tidak cek arity/nama fungsi

factors/coder/expr_parser.parse_expression hanya:
  - cek balance kurung
  - cek operator invalid (karakter)
  - parse grammar infix

TIDAK cek arity atau validitas nama fungsi. Konsekuensi: ekspresi
crossover "TS_ZSCORE($volume, $return, 20)" (3 argumen, 2 field) LOLOS
gate walau DSL-nya salah secara semantik. Ini bukan crash — hanya
kualitas factor tidak optimal.


### 5. KNN + latent virtual tokens: inkompatibilitas struktural (TEMUAN BARU)

Run: session_20260601_123306 (latent_steps=40, use_realign=True, knn=True)
Sumber data: events.jsonl + llm_outputs session 20260601_123306

Hasil setelah fix RoPE re-rotasi (commit 53f7397):
  - judger:              output_tokens=1, text_len=0 — EOS dini, bukan
                         echo panjang. Perubahan dari sebelum fix (echo
                         template "1 1 1..."), tapi masih gagal.
  - repair:              output_tokens=17-28, parsed valid ("TS_ZSCORE(
                         $volume, 20)", "TS_ZSCORE($return, 20) / TS_STD(
                         $volume, 20)"). BERHASIL — repair terbukti sehat.
  - mutation_reflection: output_tokens=512 full "1. 1. 1..." degenerate.
  - mutation_judger:     output_tokens=1024 "的 1 1 1..." degenerate.
  - crossover_judger:    output_tokens=1024 "和 3 3..." degenerate.

Pola seq_len di events.jsonl (parent-1):
  proposal    : 155 tokens  (kv_only)
  construct   : 378 tokens  (kv_only, menerima proposal KV)
  consistency : 496 tokens  (kv_only, menerima construct KV)
  judger      : 649 tokens  (kv_and_text, deepcopy kv_consist 496 → +153)
  repair      : 653 tokens  (berangkat dari kv_consist 496 — BUKAN kv_judger)
  mutation_reflection: 736 tokens (menerima kv_judger 649)
  mutation_judger: 1338 tokens (menerima kv_reflect 736)
  crossover_judger: merged 1300 tokens (kv_p1=650 + kv_p2=650 cat)

Mengapa repair berhasil tapi judger gagal (keduanya mulai dari kv_consist):
  Repair: prompt singkat, format sederhana "FIXED: <expr>" → lebih robust
  terhadap KV yang terdistorsi.
  Judger: prompt lebih panjang + complex, dua-baris output → lebih sensitif.

Akar masalah SEBENARNYA — inkompatibilitas struktural KNN + virtual tokens:
  Setiap agent kv_only menambahkan 40 latent VIRTUAL TOKENS ke KV cache.
  Virtual token ini tidak punya representasi teks; posisinya di-inject
  langsung ke hidden state tanpa teks/position_id yang jelas.

  Ketika agent BERIKUTNYA menerapkan KNN pada cache sebelumnya, ia
  memfilter campuran dari:
    a) Real text tokens  (posisi 0..n, makna semantis jelas)
    b) Virtual latent tokens (posisi n+1..n+40, makna implisit)

  Setelah filter + re-rotasi ke posisi kontigu, virtual token yang
  tersisa berada di posisi baru yang TIDAK SESUAI dengan bagaimana
  model mengharapkan virtual token diposisikan relatif terhadap real
  tokens. Re-rotasi benar untuk token nyata (RoPE additif terbukti),
  tapi tidak memulihkan relasi posisi yang benar untuk virtual tokens
  yang embedding-nya dihitung dalam konteks posisi asli mereka.

  Akibatnya setiap pass KNN menambah distorsi sedikit, dan setelah 4-5
  agent (proposal→construct→consistency→judger→mutation_reflection),
  distorsi terakumulasi cukup besar untuk menyebabkan collapse total.

Bukti: repair (1 level KNN, berangkat dari kv_consist fresh) berhasil;
judger (1 level KNN dari kv_consist, tapi lebih kompleks) gagal; evolution
agents (2-3 level KNN terakumulasi dari kv_judger) collapse penuh.

Kesimpulan: KNN dan latent_steps > 0 TIDAK KOMPATIBEL dalam desain ini.
KNN harus dinonaktifkan saat latent_steps > 0. Fix yang benar untuk
kombinasi keduanya memerlukan rancangan ulang lebih dalam (misalnya:
terapkan KNN HANYA pada real tokens sebelum virtual tokens ditambahkan,
dengan tracking posisi virtual vs real secara eksplisit).


### 4. Bocoran tag <think> dari Qwen3

Qwen3-4B kadang menutup </think> tanpa <think> pembuka (orphan tag),
atau memendekkan label output:
  - HYPOTHESIS: → HYPOTH: / HYPOTHS:
  - EXPRESSION: → EXPR:
Akibatnya parse_hypothesis_expr mengembalikan hypothesis="" walau
ekspresi berhasil di-parse.

## GAMBARAN ARSITEKTUR RINGKAS (UNTUK ORIENTASI)
=======================================================================

FrontEndPipeline.run():
  proposal(kv_only) → construct(kv_only) → consistency(kv_only)
  → kv_consist [baseline pristine]
  → judger(kv_and_text, deepcopy kv_consist)
  → _gate_and_repair(expression, kv_consist)
  → FrontEndOutput{hypothesis, expression, kv_consist, kv_judger}

EvolutionOps.mutate(parent_kv_judger):
  mutation_reflection(kv_and_text, parent_kv_judger)
  → mutation_judger(kv_and_text, kv_reflect)
  → EvolutionOutput{hypothesis, expression}

EvolutionOps.crossover([kv_p1, kv_p2]):
  kv_concat([kv_p1, kv_p2]) → layer-wise concat
  → crossover_judger(kv_and_text, kv_merged)
  → EvolutionOutput{hypothesis, expression}

KV chain: setiap agent menerima past_kv dari agent sebelumnya.
  Mode kv_only  : hanya bangun konteks, tidak generate teks.
  Mode kv_and_text : latent_pass dulu (tanpa assistant prefix),
                     lalu generate_from_kv (kirim prefix token saja
                     sebagai trigger, hindari double-encoding).

LocalLLMBackend._engine = _CoreEngine (Qwen3-4B, bfloat16, CUDA).
KNN filter: kv_knn_filter dipanggil di awal latent_pass & generate_text
            jika knn_enabled=True — SETELAH fix, key dire-rotasi ulang.
