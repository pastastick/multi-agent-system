2026-06-08 (lanjutan [[latentmas-rework]], submodule `newEvol`; kode di
`/workspace/project/multi-agent-system/backend`): mengubah alur evolution dari
**JUDGER-ONLY** (mutation/crossover langsung emit hypothesis+expression) menjadi
**GUIDANCE → re-entry front-end**, atas permintaan user.

**Maunya user:** mutation/crossover hanya menetapkan ARAH (knowledge/observation/
diagnosis/direction) sebagai konteks laten; lalu propose→judger yang menyusun
ekspresi. Alur: guidance(kv_only) → proposal → construct → consistency → judger →
gate/repair → backtest → feedback → [generasi berikut] guidance baru → ...

**Keputusan KV (user): BOUNDED PER-GENERASI.** guidance di-seed `past_kv=None`,
baca parent sebagai TEKS; KV-nya menyemai proposal HANYA dalam 1 generasi;
`trajectory.kv_cache` tetap None → transfer antar-generasi via teks
(`_format_parents_text`). KV per ronde ≈ guidance + front-end ≈ 3k → TIDAK
mengulang collapse 2026-06-02 (dulu karena warisan KV parent lintas generasi,
3.5k→21k). Opsi "kontinu lintas-generasi" sengaja DITOLAK.

**Perubahan kode (implemented + static-verified, BELUM GPU-tested):**
- `latent_mas/prompts.yaml`: rename `mutation_judger`→`mutation`,
  `crossover_judger`→`crossover`; `kv_and_text`→`kv_only`; hapus parser/
  max_new_tokens; prompt ditulis ulang jadi DIAGNOSIS+DIRECTION (tanpa ekspresi,
  tanpa embed operator-lib). Tetap 9 agent.
- `latent_mas/pipeline.py` `run_evolution`: guidance agent (kv_only, seed None) →
  `guidance_kv` → `return self.run(direction=, seed_kv=guidance_kv)`. Debug opsional
  `LATENTMAS_EVO_DEBUG=1` → decode guidance_kv via agent `introspect`. + `import os`.
- `pipeline/loop.py`: `_evolution_propose`/`_format_parents_text`/
  `_get_trajectory_data` TAK berubah logikanya (FrontEndOutput kompatibel,
  pipeline_kv tetap None); hanya komentar di-update. controller.py tak disentuh.

**Verifikasi:** statik PASSED (py_compile pipeline/loop/run_evolution; yaml 9 agent;
render StrictUndefined-safe). load_all_agents + GPU run BELUM (box dev tanpa
torch/transformers → jalan di runpod). Rencana GPU: `experiments/run_evolution.py
--mode both` (cek urutan caller guidance→propose→…→judger, KV ≈3k tak naik antar
ronde), lalu factor_mining max_rounds=3.

**Diagnosa run `log/2026-06-08_04-45-37-493118` (PRA-rework):** berjalan benar,
berhenti normal via max_rounds=3 (O→M→C→M); crossover = 1 fase = 2 trajectory
(BUKAN bug). Round terakhir asimetris (1 direction) = quirk: cek max_rounds di
puncak `get_next_task` tapi `_get_crossover_task` naikkan round lalu langsung
`_get_mutation_task`. KV TIDAK collapse (fix judger-only bekerja). GPU mem naik
monoton ~600MB/loop (8.4→12.7GB) → risiko OOM run panjang.

**Resume: SUDAH di-wire (2026-06-08, static-verified, BELUM dites e2e).** Set
`evolution.resume_from: <prev_run_dir>` di config (atau CLI `--resume_from`). Di
`run_evolution_loop`: salin trajectory_pool.json lama → log_root baru + fresh_start
=False (pool load saat controller init) + `controller.load_state(evolution_state.json)`
(restore cursor round/phase/mutation_targets). Trajectory selesai TAK di-backtest
ulang. CATATAN: bila run lama sudah mentok max_rounds, NAIKKAN `evolution.max_rounds`
atau resume langsung selesai tanpa task baru (ada warning). `main()` punya param baru
`resume_from`; contoh ter-komentar di `configs/experiment.yaml`.

**Sisa follow-up (out-of-scope):** GPU mem leak ~600MB/loop (risiko OOM run panjang);
latent_steps 10→40-80. Lihat [[quantaalpha-paper-code-divergences]].
