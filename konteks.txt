Temuan prompt (dari sesi debug 2026-06-08, baru saja saya perbaiki):

Anchoring contoh = mode collapse. Satu kalimat contoh di system prompt proposal membuat ~18 hipotesis lintas-sesi semuanya jadi varian "low-volume + volatility → mean-reversion". Ini bukan masalah kapasitas model — ini masalah prompt. Sudah diganti dengan 10 mechanism family + larangan eksplisit.
Repair-on-empty membuang 57% waktu run menghasilkan sampah. Sudah di-guard.
Soft /no_think + temp 0.4 + tanpa repetition_penalty = sumber collapse token. Sudah diganti hard switch + penalti.
Temuan workflow struktural (dari kode + memory): keputusan KV bounded-per-generasi sengaja memutus warisan KV antar-generasi (anti-collapse) — transfer antar-generasi murni lewat teks _format_parents_text. Ini benar untuk stabilitas, tapi berarti "pembelajaran" laten LatentMAS hanya hidup dalam 1 generasi.

Apakah ini benar-benar "Reinforcement Learning"? — Tidak, dan di situ ruang upgrade terbesar
Yang Anda sebut "RL" saat ini sebenarnya evolutionary search (GA) + in-context feedback, bukan RL dalam arti pembaruan kebijakan. Bobot Qwen3 tak pernah berubah; "belajar" hanya terjadi sebagai teks yang dioper ke generasi berikut. Itu sah, tapi ada gap konkret terhadap formalisme paper (Eq.2 R(τ)=L(fτ)−λ·R(fτ)):

Gap	Kondisi sekarang	Ruang upgrade
Reward tidak pernah jadi skalar	L = per-factor RankIC; −λR = gate biner; λ tak ada di mana pun → efektif λ=0	Hitung R(τ) skalar tunggal (IC − λ·complexity_cont) sebagai fitness eksplisit; ekspos λ di config. Ini membuat trade-off kualitas↔kompleksitas bisa di-tune, bukan hard cutoff.
Seleksi parent greedy	select_crossover_pairs pakai "best" / diversity-weighted, tanpa eksplorasi terukur	Tambah eksplorasi terstruktur: softmax(reward/τ), UCB, atau ε-greedy pada pemilihan parent. Greedy murni → terjebak optimum lokal (persis yang terlihat: semua anak satu spesies).
Tidak ada credit assignment	"diagnosis" mutation = judgment LLM, tak ter-grounding	Per-factor IC sudah ada → bisa attribute reward ke ekspresi mana yang menyumbang, lalu feed angka itu (bukan prosa) ke mutation director.
is_successful terlalu lemah	IC > 0 apa pun lolos	Ambang bermakna (mis. IC ≥ 0.02 + ICIR ≥ 0.5), kalau tidak pool penuh noise yang dianggap "sukses".
Tidak ada memori kegagalan lintas-generasi	Tiap generasi mulai dari teks parent saja	Simpan negative list hipotesis/struktur yang sudah gagal, inject ke prompt proposal → memutus pengulangan (sinergis dengan fix anchoring hari ini).
Objektif terbelah	Seleksi pakai FactorIC_mean, replace-SOTA pakai annualized_return	Dua keputusan, dua metrik berbeda, bisa saling tarik. Pertimbangkan satu reward multi-objektif atau Pareto frontier eksplisit.
Catatan penting: RL "sejati" (update bobot via PPO/GRPO terhadap reward IC) adalah lompatan besar dan kemungkinan di luar cakupan (butuh training loop + GPU jauh lebih besar). Yang realistis & berdampak adalah memperkuat lapisan bandit/evolutionary di atas: reward skalar + eksplorasi terukur + negative memory. Itu memberi 80% manfaat "RL" tanpa fine-tuning.

Quality-check faktor: ada fondasi bagus, tapi cek statistik masih tipis
Yang sudah ada (kuat): FactorRegulator penuh — validasi arity/signature, complexity (SL/PC/ER), redundansi via match_alphazoo (subtree duplikat ≤ 8). ComplexityChecker deterministik. Per-factor RankIC OOS (2021+). Gate dipasang per-ekspresi sebelum backtest.

Gap & ruang upgrade:

Redundansi hanya sintaktik, bukan statistik. match_alphazoo mendeteksi subtree mirip, tapi dua formula yang strukturnya beda bisa berkorelasi ~0.95 pada nilainya → alpha redundan lolos. runner.py:307 sudah meng-log combined_factors.corr() tapi tidak dijadikan gate. Upgrade berdampak tinggi & murah: tolak/penalti faktor baru jika |corr| dengan faktor library > ambang (mis. 0.7).

Per-factor IC hanya rata-rata, tanpa stabilitas. Belum ada ICIR (IC/std(IC) → reliabilitas), t-stat, atau analisis decay. Faktor IC=0.05 tapi tak stabil sama buruknya dengan noise. ICIR murah dihitung dari deret IC harian yang sudah ada di _compute_factor_ic.

Tidak ada deteksi overfit IS↔OOS. Satu-satunya proxy overfit = complexity warning. Tambah cek gap IC in-sample vs out-of-sample; gap besar = overfit, terlepas dari kompleksitas.

Tidak ada koreksi multiple-testing. Mining banyak faktor → false positive pasti muncul. Tak ada deflated Sharpe / Bonferroni. Untuk skripsi ini poin metodologis yang kuat untuk disebut.

Complexity = char-count (SL = len(expr), ambang 300), dengan transform -log(1-ratio)<0.693 yang secara aljabar cuma ratio<0.5 (vacuous — sudah dicatat di [[quantaalpha-paper-code-divergences]]). AST depth/node-count akan jauh lebih bermakna daripada hitung karakter.

replace-SOTA = skalar in-memory tunggal, bukan frontier. Tak menyimpan riwayat untuk anti-regresi.

PERBAIKAN SESI 2026-06-14 (lanjutan) — L-1 Correlation Gate
═══════════════════════════════════════════════════════════════════════════

MASALAH: Template-collapse menghasilkan faktor-faktor berkorelasi tinggi di
NILAI aktual meski sintaks berbeda. Gate sintaktik (match_alphazoo, dedup IC>0.99)
buta terhadap ini. runner.py sudah meng-log new_factors.corr() tapi tidak dijadikan
gate. deduplicate_new_factors() di runner.py adalah DEAD CODE (tidak pernah dipanggil).

DUA LEVEL GATE:
  (1) Within-round: pairwise Pearson |corr| antar kolom new_factors ronde ini.
      Drop faktor dg IC lebih rendah dari pasangan yg berkorelasi. Gratis karena
      new_factors sudah ada di memori sebelum LightGBM.
  (2) Cross-round: cek faktor baru terhadap persistent store (daily cross-sectional
      mean per faktor, OOS window). Kompak: ~250 baris × N faktor, 2KB/faktor.
      Store hanya menyimpan faktor dg IC>0 (tidak tercemar faktor gagal).

CALL SEQUENCE DI develop():
  process_factor_data → new_factors
  _compute_factor_ic  → factor_ic, factor_icir
  _correlation_gate   → filtered_factors, dropped  ← titip sisip baru
  update exp.factor_ic/icir (hapus dropped dari dict)
  _update_corr_store  → simpan faktor yg lolos ke store
  save parquet + LightGBM backtest (existing, tidak berubah)

STRUKTUR DATA BARU:
  exp.correlation_dropped = list[str]  — "{nama} [{reason}]" per faktor yg di-drop
  data/factorlib/factor_corr_store.parquet — persistent store, kolom = factor names,
    index = datetime (daily cs-mean OOS period)

THRESHOLD:
  Default 0.7. Ekspos via:
  - experiment.yaml: evolution.corr_gate_threshold
  - env var: FACTOR_CoSTEER_CORR_GATE_THRESHOLD
  Chain: experiment.yaml → factor_mining.py (os.environ.setdefault) →
         FACTOR_COSTEER_SETTINGS.corr_gate_threshold → runner._correlation_gate()
  0.0 = gate nonaktif (semua faktor lolos, store tetap tidak diupdate).

  loop._evolution_propose: front.run_evolution(negative_hint=...) [mutation/crossover]
  pipeline.run/run_evolution → proposal agent (HANYA proposal — altitude mekanisme,
